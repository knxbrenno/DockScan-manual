What DockScan recognizes

The systems, languages, programs, services and formats that DockScan can read, and what it looks for in each one. Anything not on this list is not analyzed. Items in development are not read yet: they are the next steps for the tool.

Operating systems

System packages are read on machines, in containers and in images. For all of these, DockScan also warns when the version reaches the end of security support.

  • Debian

    Community Linux distribution, the base of many official images.

    dpkg packages, including in distroless images, and Debian advisories.

  • Ubuntu

    Canonical's Linux distribution, common on servers and in the cloud.

    dpkg packages and the Ubuntu advisories for each version.

  • Alpine Linux

    Minimal distribution, the base of many container images.

    apk packages, by Alpine version.

    In development: the Alpine security database itself, for cases where OSV records the wrong fix.

  • Rocky Linux

    Distribution compatible with Red Hat Enterprise Linux.

    RPM packages and Rocky Linux advisories.

  • AlmaLinux

    Distribution compatible with Red Hat Enterprise Linux.

    RPM packages and AlmaLinux advisories.

  • Linux kernel

    The core of the operating system.

    The version running on each machine, with the total number of CVEs and the ones that matter now.

For these, DockScan already warns about the end of support. Checking their packages is in development.

  • Red Hat Enterprise Linux

Programming languages

Dependencies are read from the project files, from the packages installed on machines, in containers and in images, and from programs that are already compiled. Outside the package manager means installed without apt, apk or dnf, as in the official images: the version comes from the file itself, without running anything.

  • Python

    Language for automation, data and web applications.

    requirements.txt, poetry.lock, Pipfile.lock and the installed packages. Also Python outside the package manager.

    In development: the uv.lock file.

  • Node.js

    JavaScript on the server, with npm packages.

    package-lock.json, yarn.lock and node_modules. Also Node outside the package manager.

    In development: the pnpm-lock.yaml and bun.lock files.

  • Go

    Compiled language, common in infrastructure tools.

  • Ruby

  • PHP

    Language for websites and web systems, with Composer packages.

  • Rust

Where the data comes from

  • OSV

    Open vulnerability database, maintained by Google.

    The advisories for packages, distributions and Bitnami.

  • KEV

    Catalog of exploited vulnerabilities from CISA, the US cybersecurity agency.

    Marks the findings under active exploitation.

  • EPSS

    Score from FIRST for the likelihood of exploitation in the next 30 days.

    Ranks the priority of findings.

  • endoflife.date

    End-of-support dates for systems and programs.

    Warns when the system version goes out of support.

How to use

See the path a scan follows and what each feature of the interface is for. The following chapters go through the steps in detail, with the screen for each one.

The complete flow, step by step

  1. Choose the target

    Open Novo scan (New scan) to enter the machine IPs. For IPs, ports and services, follow the network tutorial.

  2. Fill in the input and the policy

    Enter the IP addresses and set up SSH access in Frota (Fleet). Set the severity that should fail the scan and choose whether to compare it with a previous scan.

  3. Start and follow the scan

    Click “Iniciar varredura por IP” (Start IP scan) or, for a network, “Iniciar varredura” (Start scan). Wait for it to finish and check any error messages and coverage warnings.

  4. Investigate the findings

    In Resultados (Results), filter the items and read the location, details and recommendation. The “Passou” (Passed) and “Falhou” (Failed) states refer to the configured policy.

  5. Fix and scan again

    Change the target and run another compatible scan. Use Comparar scans (Compare scans) to check which items are new, which persist and which are no longer reported.

  6. Keep the result and set up a routine

    Export the report in the format you need. To repeat the scan, set up a schedule.

What each menu item does

Painel (Dashboard)

Shows the latest findings per target, the recent scans and the urgent items.

Check the summary and open a scan under “Scans recentes” (Recent scans). Click a severity count, or “Ver em Achados” (View in Findings), to open those findings already filtered. See guidance.

Novo scan (New scan)

Scans the system and the containers of the machines you select by IP.

Enter the IPs, review the policy and start. See the steps.

Resultados (Results)

Keeps the history and lets you investigate the findings of each scan.

Find the scan, open the result, apply filters and read the details. See the steps.

Achados (Findings)

Brings together in one table the findings from the latest scan of each target, with an SQL-like query, the state of each finding over its history, triage with deadlines, tags and saved views.

Click the query box, choose a field, an operator and values, and run the query. See the steps.

Inventário (Inventory)

Gathers the machines, containers and services from your scans on a map and in a list. Machines discovered in the cloud come in by IP, together with those from the fleet and the network.

Click a machine to expand its items, select a resource to see its details and use the filters to find an IP or service.

The map reads the saved data. Historical states and dates help you spot old or incomplete collections. The ranges are visual groupings of the IPs.

Frota (Fleet)

Saves the inventory of hosts whose containers will be scanned.

Add the hosts, save and use “Configurar varredura” (Configure scan). See the steps.

Nuvem (Cloud)

Registers cloud accounts and Kubernetes clusters with read-only credentials. AWS can already be read; the other providers arrive in upcoming stages.

Choose the provider, fill in the fields, test the connection and use “Descobrir agora” (Discover now). See the steps.

Buscar CVE (Search CVE)

Checks for a CVE or GHSA live on the IPs you enter, with a fresh collection over SSH.

See the investigation steps.

Allowlist

Suppresses findings you have already assessed from upcoming scans and from the policy evaluation.

Enter one entry per line, review its scope and save. See the steps.

Rede (Network)

Brings together network scanning, hosts, services, Docker exposure, registries, TLS certificates and network findings.

Start with “Varrer a rede” (Scan the network) and investigate the results on the module's screens. See the steps.

Agendamentos (Schedules)

Repeats scans with a saved interval and input.

Set the name, type, interval, time, target and policy. See the steps.

Baselines

Compares compatible scans and shows how the findings changed.

Select the current scan and the reference, and review the groups. See the steps.

Auditoria (Audit)

Lets you look up the access and operation records of the interface.

Open the menu and search by user, action, target or result. See the steps.

Configurações (Settings)

Shows instance information, upload limits and network options.

Check the connection and adjust the scope and the network options. See the steps.

The Rede screens

Summarizes the selected scans. Choose the scans and filter by IP or severity to see the indicators.

Creates a scan. Enter the authorized targets, review the profile, ports and modules, and click “Iniciar varredura”.

Perfis (Profiles)

Saves combinations of ports, discovery and audits. Create a profile or duplicate an existing one, adjust the fields and save.

Allowlist: how to add an exception
  1. Open “Allowlist” in the menu.
  2. Enter one rule, package location or identifier per line. Use lines starting with # for comments.
  3. Review the entry and click “Salvar allowlist” (Save allowlist).
  4. Run a new scan to apply the change. Earlier history stays as it was.

A package entry can suppress several vulnerabilities. Check the scope of the exception before saving.

Auditoria: how to find an activity
  1. Open “Auditoria” in the menu.
  2. Fill in “Buscar atividade” (Search activity) with a user, action, target or result.
  3. Check the date, user, action, target, IP and result of the activity found.
  4. Clear the search to go back to the available list.
Configurações: what to check and how to adjust the network
  1. Open “Configurações” to see the version, the connection and the upload limits.
  2. In “Configurações de rede” (Network settings), review the authorized scopes, the exclusions and the scan limits.
  3. Also check the report format, the evidence and the interface preferences.
  4. Click “Salvar configurações de rede” (Save network settings). Changes to the scope and to global limits require that no scans are running.

Review the confirmation before reducing retention: this change can delete old network scans and their reports.

Achados de rede: how to record triage
  1. Open “Rede → Achados de rede”.
  2. Find the finding using the filters and open its details.
  3. Read the evidence and write the reason in “Comentário de triagem” (Triage comment).
  4. Choose the action: revisado (reviewed), falso positivo (false positive) or risco aceito (accepted risk). Use “Reabrir” (Reopen) to reopen a finding.

Triage records your assessment of the item. Check the evidence and the coverage of the scan before deciding its state.

Manual images

The screens for each step come from the DockScan lab, with demo data. Screens and names may change while the tool is under development.

Your first IP scan

Enter the machines' addresses. DockScan collects the data over SSH and automatically identifies the installed packages.

  1. Set up SSH access

    In Frota (Fleet), add a credential to the vault with the scope of allowed IPs, or set up an SSH key in the inventory.

  2. Open “Novo scan” (New scan) and enter the IPs

    Type one IP per line or separate them with commas. The inventory buttons add IPs that are already registered. The selection can include IPv4 and IPv6.

  3. Set the scan policy

    Choose the minimum severity that fails the scan and the options for CVEs, KEV and EPSS. Leave comparison checked to track changes on the same IPs.

  4. Click “Iniciar varredura por IP” (Start IP scan)

    The result updates automatically. The collection uses only the IPs you entered, even if there are other machines in the inventory.

How the data is obtained

Package names and versions are discovered on the machine itself. You don't need to enter or upload any package to start the scan. The remote commands only read data, without installing an agent.

What does the scan collect?

It reads the system packages and configuration, the containers and the available data about processes and ports. The result reports access failures and any parts of the collection that were left incomplete.

“Pular consulta de CVEs” (Skip CVE lookup) turns off the vulnerability lookup. “Pular KEV e EPSS” (Skip KEV and EPSS) turns off that enrichment. Having no findings in an incomplete collection does not rule out vulnerabilities.

Understand the results

The result shows what was found, where the problem is and what the recommended next step is.

  1. Check the state and the warnings

    Open the scan from the Painel (Dashboard) or from Resultados (Results). See whether it finished, whether there was an error and which limits or lookups affected the coverage.

  2. Filter what you need to investigate

    Use Severidade (Severity) and Buscar achado (Search finding) to find a rule, package, CVE or location. Under Exibir (Show), switch between “Pacotes e regras” (Packages and rules) and “Vulnerabilidades individuais” (Individual vulnerabilities).

  3. Open the details and read the recommendation

    Each item shows its severity, rule identifier and location. Use Ver detalhes (View details) to see the evidence and plan the fix. When available, KEV and EPSS help you prioritize.

About the policy

“Passou” (Passed) can appear even when there are findings

The state tells you whether the threshold of the chosen policy was reached. A scan whose findings are all below the configured threshold can pass. Check the policy, the warnings and the coverage before concluding that the target is safe.

Crítica (Critical)Alta (High)Média (Medium)Baixa (Low)Info

A package finding can group several vulnerabilities. The individual view helps you check each identifier without confusing the number of packages with the number of vulnerabilities.

What is the difference between “Falhou” (Failed) and “Erro na análise” (Scan error)?

“Falhou” and “Passou” are the result of the policy: the scan finished, and some finding did or did not reach the configured threshold. “Erro na análise” is a technical failure: the collection did not finish. It is shown with a red dotted underline so it is not confused with “Falhou”. “Incompleto” (Incomplete) means part of the coverage is missing.

Query the findings

The Achados (Findings) screen brings together in a single table the findings from the latest scan of each target, from every source. An SQL-like query finds what you need.

  1. Open “Achados” in the menu

    The table starts with all findings, from most to least urgent: first by priority, then the actively exploited ones (KEV), by severity and by likelihood of exploitation (EPSS).

  2. Click the query box and choose a field

    The list shows the fields. Hover over a field to open its options next to it: choose the operator, check one or more values and click “Adicionar à consulta” (Add to query). The suggested values come from your own findings, with the count for each one.

  3. Combine conditions and run the query

    Once you have a query, click the box again to continue with “e” (and), “ou” (or) or “ordenar por” (order by), or use “Adicionar outro filtro” (Add another filter). Then click “Consultar” (Query) or press Enter. If you already know the language, you can type the query directly.

  4. Group, sort, share and export

    In “Agrupar por” (Group by), view the findings by asset, vulnerability, package, source, state or tag; click a group to filter just that group. Click a column header to sort. The query is kept in the page address, so you can share the link. “Exportar CSV” (Export CSV) and “Exportar JSON” (Export JSON) export the query result.

  5. Open the details of a finding

    Click the identifier, such as CVE-2023-44487, or anywhere in the Achado (Finding) column. A panel opens on the right with CVSS, EPSS, active exploitation, where the finding is, how to fix it, the OSV description and references, the other assets with the same vulnerability and the collection history of the asset. From there you can triage it and move to the previous or next finding in the query; Esc or “Fechar” (Close) takes you back to the table.

  6. Triage the findings

    Select the findings in the first column. In the bar that appears, choose Revisado (Reviewed), Falso positivo (False positive), Risco aceito (Accepted risk) or Reabrir (Reopen), enter the deadline, if there is one, and the reason, and click “Aplicar triagem” (Apply triage). Falso positivo and Risco aceito require a reason; everything is recorded in Auditoria (Audit).

severidade >= alta e corrigivel
pacote ~ openssl e (fonte = maquina ou fonte = container)
cve em (CVE-2022-37434, CVE-2024-3094)

Where the findings come from

The table uses the latest completed scan of each target. In the fleet, each machine counts separately: if a machine was unreachable in the newest scan, its last good collection is used. CVE searches are not included, because the same packages already show up through the fleet.

Fixed findings, false positives and accepted risks stay out of the table until the query mentions them. The summary says how many are hidden and has a shortcut to show them.

States of a finding over its history
StateWhen it appears
Novo (New)The finding had never appeared on this target before.
Ativo (Active)It has been present since the previous collection.
Reapareceu (Reappeared)It had disappeared in a complete collection and came back.
Corrigido (Fixed)It stopped appearing in a complete collection. A partial collection does not prove the fix: the finding stays active, with the partial collection warning. A warning such as “regras do sudo não verificadas” (sudo rules not checked) only marks as partial the findings that depend on it.
Where does the data in the finding panel come from?

CVSS, EPSS, active exploitation, package and fix come from the scan. The description, dates, weakness (CWE) and references come from OSV: the DockScan server fetches them when you open the panel and keeps them for a day. Without internet, the panel shows everything else and says that OSV did not respond.

The history shows the latest collections of the asset: Encontrado (Found), Não encontrado (Not found) or Coleta parcial (Partial collection), when the absence does not prove the fix. The page address gets ?achado=, so the link opens straight on the same finding.

How does DockScan set the priority?

Each vulnerability gets one of four priorities, and the screen shows the reasons for each one:

  1. Corrigir agora (Fix now): actively exploited (KEV); likelihood of exploitation (EPSS) of 10% or more with the package in use or reachable over the network; or critical and reachable over the network.
  2. Esta semana (This week): EPSS of 10% or more; or critical or high that has EPSS of 1% or more, is in use or is reachable over the network.
  3. Planejar (Plan): the other critical and high ones, those with EPSS of 1% or more and the medium ones that already have a fix.
  4. Acompanhar (Track): everything else.

An installed package that no process loads drops one level. Configuration findings, which have no CVE, follow the severity. To query, use prioridade = agora, em_uso or exposto.

Which fields can I query?

severidade (severity), cve, regra (rule), titulo (title), pacote (package), versao (version), ecossistema (ecosystem), correcao (fix), corrigivel (fixable), fonte (source), ativo (asset), ip, porta (port), container, local (location), epss, kev, prioridade (priority), em_uso (in use), exposto (exposed), novo (new), visto_em (seen at), estado (state), triagem (triage), primeiro_visto (first seen), corrigido_em (fixed at), prazo (deadline), tag and scan. The “Como consultar” (How to query) help on the screen itself describes each one.

A yes/no field on its own means “sim” (yes): kev is the same as kev = sim. Dates accept 2026-11-01, -7d, +30d, -24h, hoje (today) and ontem (yesterday). EPSS accepts 0.1 or 10%.

How does the triage deadline work?

Revisado, Falso positivo and Risco aceito can have a deadline of up to two years. When the deadline passes, the finding goes back to aberto (open) and reappears in the table, marked as prazo vencido (overdue). To review the exceptions that are about to expire, query triagem != aberto e prazo < +30d.

How do I create tags and saved views?

A tag has the format category:value, such as ambiente:producao or time:plataforma, and is defined by a query. Write the query that selects the findings, click “Criar tag com esta consulta” (Create tag with this query) and enter the category and the value. Every finding that matches the query gets the tag, including those from upcoming scans. Then filter with tag = ambiente:producao or tag = ambiente:*, or group by tag. The tags are listed in the “Tags” panel, with how many findings each one marks.

A saved view stores the query and the grouping under a name. Use “Salvar como visão” (Save as view) and later pick the view in “Visões salvas” (Saved views). Tags and views apply to all users of this instance.

What is the remediation plan?

In “Agrupar por”, choose “Plano de correção” (Remediation plan). Each row is an installed package, with how many vulnerabilities it has, the worst severity, the affected assets and the version to upgrade to. Upgrading a package on the list fixes all the vulnerabilities in its row at once.

Can I query from the terminal?

Yes, with the same language as the screen, reading the interface's data:

dockscan achados severidade >= alta e kev --data-dir ~/.dockscan
dockscan achados estado = novo --formato csv > novos.csv

Without --formato, you get a table; with json or csv, you get the same data as the export on the screen.

The query showed an error

The message says what was missing and where, and the cursor moves to the spot with the problem. The most common errors are a misspelled field name, an operator that doesn't apply to the field (such as > on kev) and unclosed quotes or parentheses.

Track the fixes

Repeat the scan after changing the target and compare the results to see what changed.

  1. Run a new scan of the same target

    Use the same type of scan and the same target name. Keep the same IP selection and the same coverage options.

  2. Open “Comparar scans” (Compare scans)

    On the page of a completed result, click Comparar scans. You can also open Baselines from the menu. Select the current scan and a compatible reference.

  3. Review the three groups

    Novos (New) appeared in the current scan. Persistentes (Persistent) are still present. Corrigidos (Fixed) were in the reference and do not appear in the current result. Open the items to understand the change.

Before comparing

A disabled lookup, a collection error or a change to the allowlist can change the results. “Corrigido” means the finding is no longer reported in this comparison. Check the evidence and the warnings of both scans.

How do I handle an exception with the Allowlist?

Open Allowlist, enter one rule, package location or identifier per line and click Salvar allowlist (Save allowlist). Lines starting with # are comments.

The entries apply to upcoming scans and remove the matching findings from the failure evaluation. Earlier history stays as it was. Review the scope of each entry: one package can group several vulnerabilities.

Scan your fleet

Register your hosts to scan their running containers and their configuration, using the saved inventory.

  1. Open “Frota” (Fleet) and fill in the inventory

    Enter one IP per line, with the SSH access options. The DockScan server must be able to reach the hosts over SSH, have access by key or through the credential vault, and have permission to perform the reads. The vault is on the Frota page itself.

  2. Save and start the scan

    Click Salvar inventário (Save inventory) and then Configurar varredura (Configure scan). In “Novo scan” (New scan), select the IPs, adjust the policy and click “Iniciar varredura por IP” (Start IP scan).

  3. Review each host

    In the result, open the hosts and check the findings for the machine and for its containers. Also check for access failures and collection warnings. Go back to “Frota” to see the latest scan.

  4. See the machines in Inventário

    After the scan, “Inventário” (Inventory) shows the machines, containers and services found, in a map grouped by IP range or in a list. Click a machine to open its containers and services, and use the search and filters to find an IP.

How to set up the SSH vault
  1. In Frota, go to “Cofre de acesso SSH” (SSH access vault).
  2. Enter the name, user, password and allowed scope. Check sudo only if that account is configured to use it.
  3. Click “Salvar credencial” (Save credential). The password is cleared from the field and is never returned by the interface.
  4. In the inventory, use cred=nome-da-credencial to select it. The scope is still enforced.

The SSH identity is recorded on the first connection. If it changes, check the change before forgetting the entry in the list of known identities.

What is read on each machine

The collection only uses what the machine already has: system commands and files under /proc and /etc. You don't need to install Python or an agent. On a minimal machine, without ss or ps, the ports and processes come straight from the kernel.

  1. System packages: Debian and Ubuntu (dpkg), Alpine (apk), Rocky Linux and AlmaLinux (rpm). Other RPM distributions, such as Red Hat and Amazon Linux, show up as not verified, because OSV does not include their advisories.
  2. Debian, Ubuntu and Rocky advisories name the source package: an OpenSSL vulnerability that applies to libssl3 shows up as openssl.
  3. The kernel counts by the running version, not by the installed packages. The finding shows the total number of CVEs and lists the ones that matter now: those actively exploited, those with a likelihood of exploitation of 1% or more, those published in the last few days and the critical and high ones that an already installed kernel fixes on the next boot.
  4. Language packages (pip, npm, gems, Composer and NuGet) and Java libraries (.jar, .war, .ear), in containers and on the machine, including under /home and /root; Go binaries in both, and Rust binaries in containers. In a container without a shell, the language packages come from the application folders, copied with docker cp.
  5. Programs installed outside the package manager, such as node, python and redis in the official images: the version comes from the file itself, without running anything. The list is in What DockScan recognizes.
  6. The end of support of the system on the machine and in each container.
  7. For each vulnerable package, whether any process is using its files right now. A Go binary that is not running lowers the exposure; for Java libraries, DockScan only reports when they are in use, because a .war unpacked by the server is used without staying open.
How to investigate a CVE
  1. Open “Buscar CVE” (Search CVE) in the tool's menu.
  2. Enter the IPs and a CVE or GHSA identifier.
  3. Click “Verificar CVE nos IPs” (Check CVE on the IPs). The data is collected over SSH from the selected machines.
  4. Read the occurrences, the collection date, the warnings and the evidence of use. An incomplete collection does not rule out a target.

The packages are identified automatically during the IP collection.

Inventory example
# Docker da máquina em que o DockScan está rodando
127.0.0.1 local=true

# Exemplo de host remoto: substitua pelo seu ambiente
deploy@host.exemplo.com:2222 key=~/.ssh/id_deploy

Key paths and the local Docker are resolved on the DockScan server machine. Use only hosts you are authorized to access.

Explore the network

The Rede (Network) module identifies ports and services and gathers exposure evidence on the authorized targets.

  1. Check the allowed scopes

    In Configurações → Configurações de rede (Settings → Network settings), review “Escopos de rede autorizados (IP/CIDR)” (Authorized network scopes). Only include networks you are authorized to scan. The default allows loopback.

  2. Open “Rede → Varrer a rede” (Network → Scan the network)

    Give the scan a name. In IP, range, CIDR ou múltiplos alvos (IP, range, CIDR or multiple targets), enter the IPs and networks. To try it out on the server machine, use 127.0.0.1. You can also import a .txt list in “Importar alvos” (Import targets).

    Fill in the exclusions, if needed. Check the target estimate and the authorized scope shown in the form.

  3. Choose the profile and review the ports

    In “Configuração da varredura” (Scan configuration), select the “Perfil” (Profile) and check the “Portas” (Ports). Review the timeout, the speed and the modules “Detectar serviços” (Detect services), “Detectar Docker” (Detect Docker), “Auditar registries” (Audit registries) and “Analisar TLS” (Analyze TLS).

  4. Confirm the authorization and click “Iniciar varredura” (Start scan)

    Follow the progress on the scan page. Use “Pausar” (Pause), “Retomar” (Resume) or “Parar” (Stop) to control or end it. When you stop it, the partial results remain available.

Where to look afterwards

“Em andamento” (In progress) shows the active jobs. “Histórico” (History) keeps the previous scans. Use “Hosts” and “Serviços” (Services) to investigate the hosts and services found.

How to read the coverage

On the scan page, switch “Visualização” (View) between hosts, ports, TCP coverage, services and findings. See “Configuração e limitações” (Configuration and limitations) to understand the reach of the collection.

About coverage

A timeout is an inconclusive result

A port that doesn't respond is not proven to be closed. A host that doesn't respond is not proven to be down either. Check the coverage states before comparing or closing the investigation.

How do I compare two network scans?

Open “Comparar varreduras” (Compare scans) from the Rede menu or use “Comparar” (Compare) on the result. Select the two scans and review the new, removed, changed and unchanged items.

Items without comparable coverage show up as “NotComparable”. Confirm the targets, ports and modules before you interpret a service as removed or a risk as resolved.

Connect the cloud

The cloud module reads AWS accounts to find what exposes your containers: machines, firewall rules, registries and clusters. Azure, Google Cloud and Kubernetes can already be registered; reading them arrives in upcoming stages.

  1. Create a read-only credential

    When you choose the provider, the screen shows the minimum permission and step-by-step instructions to create the credential. Never use an administrator user's key.

  2. Open “Nuvem” (Cloud) and choose the provider

    Give the account a name and fill in the fields. Regions, subscriptions, projects or namespaces define what can be read.

  3. Save and click “Testar conexão” (Test connection)

    On AWS, the test checks access in the cloud itself and shows the identity used. For the other providers, it confirms that the account was validated and saved.

  4. Click “Descobrir agora” (Discover now)

    Discovery is a scan like any other: it opens on the scan page, is listed in Resultados (Results) and gets Falhou (Failed) or Passou (Passed) from the policy. The findings go to the Achados (Findings) screen with fonte = cloud, and the machines go to the Inventário (Inventory). If a region can't be read, the scan is marked incomplete and says which one.

  5. Edit or delete when needed

    In “Editar” (Edit), a secret left blank keeps its current value. “Excluir” (Delete) removes the account and its secrets from the server.

Security

Secrets are encrypted, but they live on the server

Credentials are encrypted with the vault key and never come back to the screen. Anyone with administrator access to the DockScan server can read them: register only read-only credentials and, preferably, ones with an expiration date.

Why was my kubeconfig rejected?

For security, the kubeconfig must have the token or the certificate embedded, and the cluster CA in certificate-authority-data. The following are rejected: authentication through exec or auth-provider, which would run a program on the DockScan server; file paths, which would read files from the server; insecure-skip-tls-verify; and addresses without https://.

What does DockScan look for in the cloud?

Administration ports open to the internet (Docker API, kubelet, etcd, Kubernetes API, registry and SSH), rules that allow all ports, registries with anonymous read access or with an admin user, mutable tags, an open cluster API, clusters without RBAC, machines that accept the metadata service without a token, and privileged workloads.

On AWS, this comes from EC2 (machines and security groups), ECR and EKS, in the registered regions. With the role ARN, the key can only be used to assume the role, in a 15-minute session, and every read uses the role. No call creates or changes resources.

“Descobrir agora” does not appear

The button appears when the provider already has a connector and its SDK is installed on the DockScan server. For AWS, install it with pip install "dockscan[cloud]". The connection test also warns you when the SDK is missing.

Schedule scans

Repeat a scan at set intervals and check the result of each run in the history.

  1. Open “Agendamentos” (Schedules) and name the routine

    Set the interval in minutes and the first run. To run once a day, use 1440 minutes. The interface accepts 5 to 10080 minutes.

  2. Fill in the target and the policy

    Enter the machine IPs and the failure criteria. The selection is saved in the routine, and SSH access uses the Frota (Fleet) settings.

  3. Click “Criar agendamento” (Create schedule)

    The routine appears under “Scans agendados” (Scheduled scans). Use Executar agora (Run now) to start a manual run, Pausar (Pause) to stop the upcoming runs and Retomar (Resume) to reactivate it. Deleting the schedule keeps the previous scans.

How the routine works

The schedule repeats the collection on the selected IPs and identifies the machines' current data. Adding more IPs to the inventory does not expand the target of a routine that already exists.

Do scans keep running with the interface closed?

Closing the browser tab does not shut down the server. Routines keep running as long as the DockScan server is running. To run them with the web server off, keep the standalone service below running, using the same data directory as your instance.

python -m dockscan agendador --data-dir ~/.dockscan

Without the server and without this service, the runs do not happen. When it comes back, the pending run takes place, without repeating all the missed runs.

Accounts and access

Each person signs in with their own username and password, and the account's role defines what they can do. Everything is managed in Configurações (Settings).

  1. Sign in with your username and password

    On the login screen, use the account's username or email. “Manter conectado” (Keep me signed in) keeps the session open for up to 7 days in this browser; without it, the session ends after 30 minutes of inactivity or after 12 hours.

  2. On your first sign-in, set your password

    Whoever creates the account gets a temporary password to pass on to you. When you sign in with it, DockScan asks you to choose your own password before opening any screen: at least 12 characters and different from the username.

  3. Check your profile in Configurações

    Click your name at the bottom of the menu. The profile shows your username, email, role and when the password was last changed. There you can adjust your name and email, change your password and see the sessions open in other browsers, with the option to end each one.

  4. Administrator: create your team's accounts

    In Usuários (Users), enter the name, username and role and click “Criar usuário” (Create user). The temporary password appears once, with the Copiar (Copy) button: send it through a secure channel. For each account, Editar (Edit) changes the name, email, role and whether the account is active; Redefinir senha (Reset password) generates a new temporary password; Excluir (Delete) removes access.

  5. Turn on two-step verification

    In Configurações, click “Ativar a verificação em duas etapas” (Turn on two-step verification), scan the QR code with an authenticator app (Google Authenticator, Microsoft Authenticator, Authy or 2FAS) and enter the 6-digit code it shows, together with your password. Keep the 10 recovery codes that appear next: each one lets you in once if you lose your phone. From then on, sign-in asks for the code after the password.

Account roles and what each one can do
RoleCan
Administrador (Administrator)Everything, including users, access keys, the SSH vault, the Frota inventory, cloud accounts and network settings.
Analista (Analyst)Run scans and CVE searches, triage findings, and edit the allowlist, views, tags and schedules.
Leitura (Read-only)View and export results and findings, without changing anything.

Whatever a role does not allow does not appear on the screen. A role change takes effect immediately, without the person having to sign in again. DockScan does not let the server be left without an active administrator, and no one can change their own role or deactivate their own account.

Access keys

A key signs in as an administrator, without a username and password. Use keys for automation and to recover access; for people, prefer an account. Generate and revoke keys in Configurações. A key is shown only once.

Requiring verification

In Usuários (Users), the administrator chooses who must use two-step verification: nobody, administrators or all accounts. Anyone who has not turned it on yet sees the activation screen before any other. To require it for a role that is yours, turn it on for your account first. Access keys do not ask for the code: keep them like administrator passwords.

I forgot my password

Ask an administrator to use Redefinir senha on your account: you get a temporary password and choose your own at your next sign-in. Your open sessions are ended.

If no administrator is available, someone with access to the server can change the password from the terminal, using the same data directory as the instance:

dockscan usuarios senha --usuario SEU_USUARIO
I lost the phone I use for two-step verification

On the sign-in screen, after the password, click “Usar um código de recuperação” (Use a recovery code) and enter one of the codes you kept. Once in, generate new codes, or turn verification off and on again with the new phone.

With no codes left, ask an administrator to use “Remover verificação” (Remove verification) on your account: your sessions are ended and the next sign-in asks only for the password. With no administrator available, from the server terminal:

dockscan usuarios remover-verificacao --usuario SEU_USUARIO
The code is not accepted

The code changes every 30 seconds and each one works once. Enter the one the app shows now and check that the phone’s date and time are set automatically. Five wrong codes in a row take you back to the password; too many errors block new attempts for 15 minutes.

Why did my session end?

A session ends after 30 minutes of inactivity, after 12 hours (7 days with “Manter conectado”), when you sign out, when another of your sessions ends it in Configurações, when you change your password (your other sessions are signed out) or when an administrator resets your password or deactivates the account. Restarting the server does not end sessions. Turning on two-step verification also ends your other sessions, and an administrator ends yours when removing your verification.

I got “O papel não permite esta ação” (The role does not allow this action)

Your account does not have permission for that action, for example editing the Frota inventory with the Analista role. Ask an administrator to make the change or to adjust your role.

Frequently asked questions

Check the state of the scan before interpreting the result.

The scan returned no findings. Is everything safe?

Check whether the scan finished, whether any filters are hiding items and whether there are warnings about failures or an incomplete collection. Also check whether the CVE lookup was turned off and whether there are entries in the allowlist. No findings means that this run did not report any items within the coverage it achieved.

An IP was not accepted

Enter the machine's IPv4 or IPv6 address, without a DNS name, user, port or range. If the SSH port is a different one, set it in the Frota (Fleet) inventory.

Could not connect to the machine

Check that the DockScan server can reach the IP, that SSH is available and that the vault credential covers that address. Read the error and the warnings of the scan to identify which parts of the collection failed.

A fleet host failed

Check the address, user, port and key path in the inventory. SSH access and the Docker query must work from the server machine. Read the per-host warnings; an access failure can prevent the collection for that target.

The network scan rejected my target

Check that you entered an IP, range or CIDR and that it is within “Escopos de rede autorizados” (Authorized network scopes). Hostnames and URLs are not valid input for this field. Also check the exclusions and host limits. Adjust the global settings when no scans are running.

Which time zone are the times in?

In your browser's time zone, with its abbreviation next to it, as in “02/11/2026, 14:21 BRT”. The server stores each time with its own time zone, so anyone opening the page from somewhere else sees the right time for them.

No new items appeared in the comparison

Confirm that there is a compatible previous reference and that comparison was turned on. Use the same IPs and the same coverage options. Review the coverage warnings, the allowlist and the “Somente novos” (Only new) filter. On the first run, there is no baseline to identify what is new.
