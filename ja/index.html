DockScan マニュアル

DockScan の
使い方を学びましょう。

最初の分析から結果の読み解きまでを説明します。必要な機能を探し、一つひとつのステップを落ち着いて進めてください。

最初のスキャンを始める機能を知る

マシン、コンテナ、ネットワークに対応。開発中のツールです。

IP でマシンを分析するSSH 経由でシステムとコンテナを分析 ネットワークを調べるホスト、ポート、サービス 結果を理解する検出結果、証拠、修正方法

出発点は Painel（ダッシュボード）です

アクセスの設定が済んだら、インターフェースを開きます。Painel には、各対象の最新の検出結果、最近の分析、対応が必要な項目がまとめて表示されます。

ローカルのインターフェースを開く場合

DockScan をインストールした状態で次のコマンドを実行し、ターミナルに表示されたアドレスを開きます。ローカルの既定のアドレスは http://127.0.0.1:8443 です。

python -m dockscan ui

このマニュアルの使い方

章を順番に読み進めるか、目次から目的の作業に直接移動してください。手順は画像を見なくても進められます。

画面は DockScan のラボ環境のもので、デモ用のデータを使っています。このガイドは、インターフェースにアクセスした後の操作から始まります。ログイン、パスワードの変更、チームのアカウント管理については、アカウントとアクセスを参照してください。

DockScan は開発中です。新しく追加された機能と今後の予定をご覧ください。

DockScan が認識するもの

DockScan が読み取れるシステム、言語、プログラム、サービス、形式と、それぞれで調べる内容です。この一覧にないものは分析されません。開発中の項目はまだ読み取られません。これらはツールの今後の予定です。

オペレーティングシステム

システムパッケージは、マシン、コンテナ、イメージで読み取ります。バージョンのセキュリティサポートが終了すると、DockScan がそのことも知らせます。ただし、Azure Linux、openEuler、Wolfi は endoflife.date が扱っていないため、対象外です。

  • Debian

    コミュニティによる Linux ディストリビューション。公式イメージの多くのベースです。

    dpkg のパッケージ（distroless イメージを含む）と、Debian のアドバイザリ。

  • Ubuntu

    Canonical の Linux ディストリビューション。サーバーやクラウドでよく使われています。

    dpkg のパッケージと、バージョンごとの Ubuntu のアドバイザリ。

  • Alpine Linux

    最小構成のディストリビューション。多くのコンテナイメージのベースです。

    apk のパッケージを、Alpine のバージョンに基づいて読み取り、Alpine 自身のセキュリティデータベースとも照合します。

  • Rocky Linux

    Red Hat Enterprise Linux 互換のディストリビューション。

    RPM パッケージと、Rocky Linux のアドバイザリ。

  • AlmaLinux

    Red Hat Enterprise Linux 互換のディストリビューション。

    RPM パッケージと、AlmaLinux のアドバイザリ。

  • Red Hat Enterprise Linux

    Red Hat の企業向けディストリビューション。UBI イメージも含みます。

    RPM パッケージと、BaseOS、AppStream、CRB リポジトリの Red Hat のアドバイザリ。

    開発中：Red Hat がまだ修正していない脆弱性。

  • SUSE Linux Enterprise

    SUSE の企業向けディストリビューション。BCI イメージも含みます。

    RPM パッケージと、各サービスパックのモジュールについての SUSE のアドバイザリ（LTSS を含む）。

  • openSUSE Leap

    SUSE のコミュニティによるディストリビューション。

    RPM パッケージと、バージョンごとの openSUSE Leap のアドバイザリ。

  • Amazon Linux

    AWS 向けの Amazon のディストリビューション。

    RPM パッケージと、Amazon Linux 2 と 2023 のリポジトリで公開されている ALAS のアドバイザリ。

    開発中：カーネル。カーネルのアドバイザリは OSV に含まれていません。

  • Oracle Linux

    Red Hat Enterprise Linux 互換の、Oracle のディストリビューション。

    RPM パッケージと、Oracle Linux 7、8、9 のリポジトリで公開されている ELSA のアドバイザリ。

    開発中：Node.js や PHP のストリームなどのモジュールパッケージと、カーネル。

  • Azure Linux

    Microsoft のディストリビューション。以前の名称は CBL-Mariner です。

    RPM パッケージと、Azure Linux 2 と 3 のアドバイザリ。

  • openEuler

    Huawei が立ち上げた、コミュニティによるディストリビューション。

    RPM パッケージと、LTS バージョンごとの openEuler のアドバイザリ。

  • Wolfi と Chainguard

    Chainguard の最小構成イメージのベース。

    apk のパッケージと、Chainguard のアドバイザリ。Alpine のアドバイザリとは区別して扱います。

  • Linux カーネル

    オペレーティングシステムの中核。

    各マシンで実行中のバージョン。CVE の総数と、今対応が必要なものを示します。

これらについては、DockScan はすでにサポート終了を知らせます。パッケージの検証は開発中です。

  • Fedora

プログラミング言語

依存関係は、プロジェクトのファイル、マシン、コンテナ、イメージにインストールされたパッケージ、コンパイル済みのプログラムから読み取ります。パッケージマネージャー外とは、公式イメージのように apt、apk、dnf を使わずにインストールされたものを指します。バージョンはファイルそのものから読み取り、何も実行しません。

  • Python

    自動化、データ処理、Web アプリケーションに使われる言語。

    requirements.txt、poetry.lock、Pipfile.lock、uv.lock と、インストール済みのパッケージ。パッケージマネージャー外の Python も読み取ります。

  • Node.js

    npm のパッケージを使う、サーバー側の JavaScript。

    package-lock.json、yarn.lock、pnpm-lock.yaml、bun.lock、node_modules。パッケージマネージャー外の Node も読み取ります。

  • Go

    コンパイル型の言語。インフラのツールでよく使われます。

    go.mod、go.sum と、Go 1.13 以降でコンパイルされ、モジュールと Go のバージョンを含むプログラム。

  • Ruby

    RubyGems のパッケージを使う、Ruby on Rails の言語。

    Gemfile.lock と、インストール済みの gem。パッケージマネージャー外の Ruby も読み取ります。

  • PHP

    Composer のパッケージを使う、Web サイトや Web システムの言語。

    composer.lock と、インストール済みのパッケージ。パッケージマネージャー外の PHP も読み取ります。

  • Rust

    メモリ安全性を重視したコンパイル型の言語。

    Cargo.lock と、cargo-auditable でコンパイルされ、依存関係が記録されたプログラム。

  • Java

    Maven のライブラリを使う、JVM の言語。

    .jar、.war、.ear（Maven の情報または Maven Central のフィンガープリントで照合。ほかのライブラリの中にあるライブラリも含む）と、pom.xml、gradle.lockfile。パッケージマネージャー外の Java も読み取ります。

  • .NET

    NuGet のパッケージを使う、C# と F# 向けの Microsoft のプラットフォーム。

    アプリケーションの .deps.json、プロジェクトの packages.lock.json と、インストール済みの .NET ランタイム。

  • Elixir

    Hex のパッケージを使う関数型言語。

    プロジェクトの mix.lock。

  • Dart と Flutter

    pub.dev のパッケージを使う、Flutter の言語。

    プロジェクトの pubspec.lock。

  • Swift

    Swift Package Manager を使う、Apple の言語。

    プロジェクトの Package.resolved。

  • C と C++

    Conan のパッケージを使う、システム開発向けの言語。

    開発中：conan.lock。OSV に ConanCenter のアドバイザリが含まれるようになった時点で対応します。

サーバーとデータベース

いくつもの公式イメージや Bitnami のイメージのように、パッケージマネージャーを使わずにインストールされ、/usr/local や /opt にコンパイルされたものと、ディストリビューションのアドバイザリの対象外となる、ベンダー自身のリポジトリのパッケージです。バージョンはファイルそのものまたはパッケージから読み取り、何も実行しません。

  • Apache HTTP Server

    オープンソースの Web サーバー。

    公式イメージのものなど、httpd 自体から読み取ります。

  • nginx

    Web サーバー兼リバースプロキシ。

    Bitnami のイメージのものなど、バイナリ自体から読み取ります。公式イメージのように、nginx.org のパッケージも読み取ります。

  • Apache Tomcat

    Java のアプリケーションサーバー。

    公式イメージのものなど、インストール先のリリースノートから読み取ります。

  • Redis

    キャッシュやキューとして使われるインメモリデータベース。

    公式イメージのものなど、redis-server 自体から読み取ります。

  • PostgreSQL

    リレーショナルデータベース。

    公式の Alpine イメージのものなど、postgres 自体から読み取ります。公式の Debian イメージのように、PGDG のパッケージも読み取ります。

  • MariaDB

    MySQL から派生したリレーショナルデータベース。

    公式イメージのものなど、MariaDB のリポジトリのパッケージを読み取ります。

  • MySQL

    Oracle のリレーショナルデータベース。

    開発中：mysqld のバージョン。OSV に MySQL のアドバイザリが含まれるようになった時点で対応します。

  • MongoDB

    ドキュメント指向のデータベース。

    公式イメージのものなど、MongoDB のリポジトリのパッケージを読み取ります。

  • RabbitMQ

    アプリケーション間のメッセージキュー。

    公式イメージのような /opt/rabbitmq の RabbitMQ と、ベンダーの rpm パッケージ。

ネットワークサービス

Rede（ネットワーク）モジュールは、ログインせずに、それぞれの応答からこれらのサービスを特定します。保護されずに露出しているものは検出結果になります。

  • SSH

    サーバーへのリモートアクセス。

    サービスのバナーからバージョンを読み取ります。

  • HTTP と HTTPS

    Web サイト、API、ダッシュボード。

    応答ヘッダーからサーバーとバージョンを読み取ります。

  • TLS 証明書

    サービスの暗号化。

    無効な証明書や、期限切れが近い証明書。

  • Docker Engine

    Docker を制御する API。

    認証なし、または暗号化なしで露出している API。

  • イメージレジストリ

    コンテナのイメージを保管する場所。

    暗号化されていないレジストリは検出結果になります。

  • MySQL と MariaDB

    リレーショナルデータベース。

    プロトコルのハンドシェイクからバージョンを読み取ります。

  • PostgreSQL

    リレーショナルデータベース。

    TLS の要求に対する応答から特定します。

  • Redis

    インメモリデータベース。

    パスワードなしで開いていると検出結果になります。

  • MongoDB

    ドキュメント指向のデータベース。

    hello コマンドへの応答から特定します。

  • Elasticsearch と OpenSearch

    データの検索と分析。

    認証なしで開いていると検出結果になります。

  • Kubernetes

    クラスターの API、各ノードの kubelet、etcd。

    匿名でアクセスできるものや、露出しているものは検出結果になります。

  • Jenkins

    継続的インテグレーションのサーバー。

    X-Jenkins ヘッダーからバージョンを読み取ります。

  • Grafana

    監視用のダッシュボード。

    ページのタイトルから特定します。

  • Kibana

    Elasticsearch の分析用ダッシュボード。

    ページのタイトルから特定します。

  • Portainer

    ブラウザーからのコンテナ管理。

    ページのタイトルから特定します。

  • FTP

    ファイル転送。

    バナーからのバージョンと、FTPS（AUTH TLS）が提供されているかどうか。提供されていない場合、ユーザー名、パスワード、ファイルは暗号化されずに送られます。

  • SMTP

    メールの送信。

    バナーからのバージョン、STARTTLS、暗号化の前に提供されるログイン。

  • RDP

    Windows のリモートデスクトップ。

    サービスの露出と、NLA が必須かどうか。認証情報を使わず、最初のネゴシエーションから判断します。

  • Prometheus

    メトリクスの収集。

    ログインなしで開いている API と設定、エクスポーターのメトリクスとバージョン。

  • RabbitMQ

    アプリケーション間のメッセージキュー。

    ログインせずに AMQP プロトコルから読み取るバージョン、TLS なしの接続、露出している管理画面。

コンテナ、Kubernetes、クラウド

  • Docker

    コンテナのプラットフォーム。

    Frota（サーバー群）を通じたマシン上の実行中のコンテナと、docker save で保存したイメージ。イメージの各パッケージについて、それを持ち込んだレイヤーと、修正がベースイメージと Dockerfile のどちらで必要か。

  • Dockerfile

    イメージのビルド手順。

    root での実行、ENV 内のシークレット、プロジェクト全体のコピーなどの悪い慣行。

  • Docker Compose

    コンテナで動くアプリケーションのサービスの定義。

    compose.yaml と docker-compose.yml：特権モード、Docker のソケット、ホストのディレクトリと名前空間、ケーパビリティ、すべてのインターフェースに開かれたデータベースと管理用のポート、バージョン指定のないイメージ、ファイルに直接書かれたパスワード、パスワードなしのデータベース。

  • レジストリのイメージ

    Docker Hub、GitHub Container Registry、その他の互換レジストリ。

    Docker を使わずにレジストリから直接イメージを読み取り、cosign の署名も確認します。

  • Kubernetes

    コンテナのオーケストレーター。

    YAML と JSON のマニフェスト：特権、root、hostPath、制限、サービスアカウントのトークン。

    開発中：Nuvem（クラウド）に登録したクラスターの読み取り。

  • Amazon Web Services

    Amazon のクラウド。

    EC2、セキュリティグループ、ECR、EKS を、読み取りのみで調べます。

  • Microsoft Azure

    Microsoft のクラウド。

    開発中：AWS と同じ形式での、アカウントの読み取り。登録はすでにできます。

  • Google Cloud

    Google のクラウド。

    開発中：AWS と同じ形式での、プロジェクトの読み取り。登録はすでにできます。

  • Helm

    Kubernetes のパッケージマネージャー。

    プロジェクトの分析で、helm template で展開した chart を、マニフェストと同じチェックで調べます。

  • Terraform

    Infrastructure as Code。

    .tf、terraform.tfvars、JSON 形式のプラン：インターネットに開かれた管理用とデータベースのポート、公開されたデータベースとバケット、開かれたクラスターの API。

  • Podman

    バックグラウンドのサービスなしで動くコンテナ。

    Frota（サーバー群）のマシン上の Podman コンテナ。root なしのものも含め、接続ユーザーのコンテナを読み取ります。

形式と連携

  • CycloneDX

    OWASP のオープンな SBOM 形式。

    分析結果の SBOM を生成し、ほかのツールの SBOM も読み取ります。この形式の VEX も読み取ります。

  • SPDX

    Linux Foundation の SBOM 形式。

    分析結果の SBOM を生成し、ほかのツールの SBOM も読み取ります。

  • OpenVEX

    該当しない脆弱性を宣言する形式。

    影響なし、または修正済みと宣言されたものは、レポートから除外されます。

  • SARIF

    静的解析の結果の形式。

    検出結果が GitHub の Security タブに表示されます。

  • GitHub Actions

    GitHub の自動化機能。

    DockScan 専用の Action。CI で DockScan を実行し、ポリシーで不合格になるとビルドを失敗させます。

  • コードリポジトリ

    プロジェクトのフォルダーと Git リポジトリ。

    フォルダー、.zip、Git の URL によるプロジェクト全体の一括分析：依存関係、Dockerfile、Docker Compose のファイル、マニフェスト、chart、Terraform、シークレット、ライセンス。

  • ライセンス

    パッケージのソフトウェアライセンス。

    アプリケーションの依存関係のライセンス：AGPL と SSPL、GPL、LGPL や MPL などの弱いコピーレフト。

  • Jira

    Atlassian のタスク管理ツール。

    検出結果からチケットを作成し、資産、パッケージ、修正を記載します。

  • チームへの通知

    メールとメッセージングアプリ。

    スキャンの終了時に重要な検出結果が見つかると、webhook（Slack、Teams、Discord）またはメールで知らせます。

データの取得元

  • OSV

    Google が管理する、オープンな脆弱性データベース。

    パッケージ、ディストリビューション、Bitnami のアドバイザリ。

  • KEV

    米国のサイバーセキュリティ機関である CISA による、悪用が確認された脆弱性のカタログ。

    悪用が確認済みの検出結果に印を付けます。

  • EPSS

    今後 30 日間に悪用される可能性を示す、FIRST のスコア。

    検出結果の優先度の順位付けに使います。

  • endoflife.date

    システムとプログラムのサポート終了日。

    システムのバージョンのサポートが終了すると知らせます。

  • Alpine のセキュリティデータベース

    Alpine 自身が公開している修正の一覧。

    OSV に誤った修正情報が記録されている場合に、Alpine のパッケージを照合します。

  • Amazon Linux と Oracle Linux のアドバイザリ

    両ディストリビューションのリポジトリで公開されている、セキュリティ修正の一覧（updateinfo）。

    OSV に含まれていない、この 2 つのディストリビューションの RPM パッケージを照合します。

  • Maven Central

    Java ライブラリの公開リポジトリ。

    Maven の情報がない jar を、ファイルのフィンガープリントで識別します。

  • deps.dev

    公開されているパッケージのデータを集めた、Google のオープンなデータベース。

    ファイルにライセンスの記載がない依存関係について、ライセンスを補います。

各商標はそれぞれの権利者に帰属し、各プロジェクトを示すためだけに表示しています。ロゴは Simple Icons プロジェクトと各プロジェクトのものです。プロトコルなど独自のロゴがない項目は汎用のアイコンで表示しています。開発中の項目は、ロゴがグレーで表示されます。

使い方

分析の流れと、インターフェースの各機能の役割を紹介します。各ステップの詳細は、それぞれの画面とともに以降の章で説明します。

全体の流れをステップごとに

  1. 対象を選ぶ

    マシンの IP を入力するには、Novo scan（新規スキャン）を開きます。IP、ポート、サービスを調べる場合は、ネットワークのチュートリアルに従ってください。

  2. 入力内容とポリシーを設定する

    IP アドレスを入力し、Frota（サーバー群）で SSH アクセスを設定します。スキャンを不合格にする重大度と、以前の分析と比較するかどうかを決めます。

  3. 開始して進行を確認する

    「Iniciar varredura por IP」（IP によるスキャンを開始）をクリックします。ネットワークの場合は「Iniciar varredura」（スキャンを開始）をクリックします。完了を待ち、エラーメッセージとカバレッジに関する警告を確認します。

  4. 検出結果を調べる

    Resultados（結果）で項目を絞り込み、場所、詳細、推奨事項を読みます。「Passou」（合格）と「Falhou」（不合格）の状態は、設定したポリシーに対する判定です。

  5. 修正して再分析する

    対象を修正し、比較可能な条件で再度スキャンを実行します。Comparar scans（スキャンの比較）を使って、新規の項目、継続している項目、報告されなくなった項目を確認します。

  6. 結果を保存し、定期実行を設定する

    必要な形式でレポートをエクスポートします。分析を繰り返すには、スケジュールを設定します。

Allowlist：例外を登録する方法
  1. メニューから「Allowlist」を開きます。
  2. 1 行に 1 つずつ、ルール、パッケージの場所、または識別子を入力します。コメントには # で始まる行を使います。
  3. 入力内容を確認し、「Salvar allowlist」（許可リストを保存）をクリックします。
  4. 変更を適用するには、新しいスキャンを実行します。過去の履歴はそのまま残ります。

パッケージのエントリ 1 つで、複数の脆弱性が除外されることがあります。保存する前に、例外の適用範囲を確認してください。

Auditoria：アクティビティを探す方法
  1. メニューから「Auditoria」を開きます。
  2. 「Buscar atividade」（アクティビティを検索）に、ユーザー、操作、対象、または結果を入力します。
  3. 見つかったアクティビティの日時、ユーザー、操作、対象、IP、結果を確認します。
  4. 検索をクリアすると、利用できる一覧に戻ります。
Configurações：確認する項目とネットワークの調整方法
  1. 「Configurações」を開くと、バージョン、接続、アップロードの上限を確認できます。
  2. 「Configurações de rede」（ネットワーク設定）で、許可されたスコープ、除外対象、分析の上限を確認します。
  3. レポートの形式、証拠、インターフェースの設定もあわせて確認します。
  4. 「Salvar configurações de rede」（ネットワーク設定を保存）をクリックします。スコープや全体の上限を変更するには、実行中のスキャンがない状態である必要があります。
  5. 「Jira」と「Avisos à equipe」（チームへの通知）で、検出結果からのチケット作成と、スキャン終了時の webhook またはメールによる通知を設定します。この設定は管理者だけが行えます。「Testar a conexão」（接続をテスト）と「Enviar um teste」（テストを送信）で、使う前に確認できます。各通知の結果は Auditoria（監査）に記録されます。

保持期間を短くする前に、確認メッセージをよく読んでください。この変更により、古いネットワークスキャンとそのレポートが削除されることがあります。

Achados de rede：トリアージを記録する方法
  1. 「Rede → Achados de rede」を開きます。
  2. フィルターを使って検出結果を探し、詳細を開きます。
  3. 証拠を読み、「Comentário de triagem」（トリアージのコメント）に理由を書きます。
  4. 操作は revisado（確認済み）、falso positivo（誤検知）、risco aceito（受容済みリスク）のいずれかを選びます。検出結果を再オープンするには「Reabrir」（再オープン）を使います。

トリアージには、その項目の評価が記録されます。状態を決める前に、証拠と分析のカバレッジを確認してください。

マニュアルの画像

各ステップの画面は DockScan のラボ環境のもので、デモ用のデータを使っています。ツールの開発中は、画面や名称が変わることがあります。

IP による最初のスキャン

マシンのアドレスを入力します。DockScan は SSH でデータを収集し、インストールされているパッケージを自動的に特定します。

  1. SSH アクセスを設定する

    Frota（サーバー群）で、許可する IP のスコープを指定して資格情報の保管庫に資格情報を登録するか、インベントリに SSH 鍵を設定します。

  2. 「Novo scan」（新規スキャン）を開いて IP を入力する

    IP は 1 行に 1 つずつ入力するか、カンマで区切ります。インベントリのボタンを使うと、登録済みの IP を追加できます。IPv4 と IPv6 をあわせて選択することもできます。

  3. 分析のポリシーを決める

    不合格とする最小の重大度と、CVE、KEV、EPSS のオプションを選びます。同じ IP での変化を追跡するには、比較のチェックを入れたままにします。

  4. 「Iniciar varredura por IP」（IP によるスキャンを開始）をクリックする

    結果は自動的に更新されます。インベントリにほかのマシンがあっても、収集の対象は入力した IP だけです。

データの取得方法

パッケージの名前とバージョンは、マシン上で直接検出されます。スキャンを始めるために、パッケージを入力したりアップロードしたりする必要はありません。リモートコマンドは読み取りのみを行い、エージェントはインストールしません。

  1. 「Novo scan」（新規スキャン）の「Projeto」（プロジェクト）パネルで、Git リポジトリの https の URL を入力するか、GitHub の「Download ZIP」で取得したものなど、.zip 形式のプロジェクトを選びます。

  3. 結果には、依存関係の脆弱性（パッケージを含むファイルごとに 1 件の検出結果）、Dockerfile、Docker Compose のファイル、Kubernetes のマニフェスト、Helm の chart、Terraform の問題、コードに残されたシークレット、注意が必要なライセンスが表示されます。

リポジトリは最新のコミットだけをクローンし、分析の終了後に削除します。対象は公開リポジトリか、URL にトークンを含めたリポジトリだけです。node_modules、.venv、vendor などのフォルダーは対象外です。chart の分析には、サーバーに helm がインストールされている必要があります。インストールされていない場合は、chart が分析されなかったことが結果に表示されます。

ターミナルでは、dockscan repo .、dockscan repo projeto.zip、または dockscan repo https://github.com/org/projeto.git を実行します。Compose のファイルを単独で分析するには、dockscan compose compose.yaml を実行します。

スキャンでは何を収集しますか？

システムのパッケージと設定、コンテナ、そしてプロセスとポートについて取得できるデータを読み取ります。アクセスに失敗した箇所や、収集が不完全だった部分は、結果に表示されます。

「Pular consulta de CVEs」（CVE の照会をスキップ）を選ぶと、脆弱性の照会が無効になります。「Pular KEV e EPSS」（KEV と EPSS をスキップ）を選ぶと、それらによる情報の付加が無効になります。収集が不完全な場合、検出結果がなくても脆弱性がないとは言い切れません。

結果を理解する

結果には、何が見つかったか、問題がどこにあるか、次に推奨される対応は何かが示されます。

  1. 状態と警告を確認する

    Painel（ダッシュボード）または Resultados（結果）からスキャンを開きます。完了したかどうか、エラーがあったかどうか、どの制限や照会がカバレッジに影響したかを確認します。

  2. 調べたい項目に絞り込む

    Severidade（重大度）と Buscar achado（検出結果を検索）を使って、ルール、パッケージ、CVE、場所を探します。Exibir（表示）では、「Pacotes e regras」（パッケージとルール）と「Vulnerabilidades individuais」（個々の脆弱性）を切り替えます。

  3. 詳細を開いて推奨事項を読む

    各項目には、重大度、ルールの識別子、場所が示されます。Ver detalhes（詳細を表示）で証拠を確認し、修正の計画を立てます。KEV と EPSS が利用できる場合は、優先順位付けに役立ちます。

ポリシーについて

検出結果があっても「Passou」（合格）と表示されることがあります

この状態は、選択したポリシーの基準に達したかどうかを示します。設定したしきい値を下回る検出結果しかないスキャンは、合格になることがあります。対象が安全だと判断する前に、ポリシー、警告、カバレッジを確認してください。

Crítica（緊急）Alta（高）Média（中）Baixa（低）Info（情報）

パッケージの検出結果 1 件に、複数の脆弱性が含まれることがあります。個別表示にすると、パッケージ数と脆弱性数を混同せずに、識別子を 1 つずつ確認できます。

「Falhou」（不合格）と「Erro na análise」（分析エラー）の違いは何ですか？

「Falhou」と「Passou」はポリシーの判定結果です。分析は完了しており、設定したしきい値に達した検出結果があったかどうかを示します。「Erro na análise」は技術的な障害で、収集が完了していません。「Falhou」と混同しないよう、赤い点線の下線付きで表示されます。「Incompleto」（不完全）は、カバレッジの一部が欠けていることを示します。

検出結果を検索する

Achados（検出結果）画面では、すべてのソースについて、各対象の最新スキャンの検出結果を 1 つの表にまとめて表示します。SQL に似たクエリで、必要な項目を見つけられます。

  1. メニューから「Achados」を開く

    表には最初、すべての検出結果が緊急度の高い順に並びます。まず優先度、次に悪用が確認済みのもの（KEV）、重大度、悪用される可能性（EPSS）の順です。

  2. クエリ入力欄をクリックしてフィールドを選ぶ

    一覧にフィールドが表示されます。フィールドにマウスを合わせると、その横にオプションが開きます。演算子を選び、値を 1 つ以上チェックして、「Adicionar à consulta」（クエリに追加）をクリックします。候補として表示される値は実際の検出結果から取られ、それぞれの件数も表示されます。

  3. 条件を組み合わせて検索する

    クエリができたら、もう一度入力欄をクリックして「e」（かつ）、「ou」（または）、「ordenar por」（並べ替え）で続けるか、「Adicionar outro filtro」（別のフィルターを追加）を使います。その後、「Consultar」（検索）をクリックするか、Enter キーを押します。クエリ言語に慣れている場合は、直接入力することもできます。

  4. グループ化、並べ替え、共有、エクスポートを行う

    「Agrupar por」（グループ化）では、資産、脆弱性、パッケージ、ソース、状態、タグごとに検出結果を表示できます。グループをクリックすると、そのグループだけに絞り込まれます。列の見出しをクリックすると並べ替えられます。クエリはページのアドレスに含まれるため、そのリンクを共有できます。「Exportar CSV」（CSV をエクスポート）と「Exportar JSON」（JSON をエクスポート）では、クエリの結果が出力されます。

  5. 検出結果の詳細を開く

    CVE-2023-44487 のような識別子、または Achado（検出結果）列の任意の場所をクリックします。右側にパネルが開き、CVSS、EPSS、悪用の状況、検出結果の場所、修正方法、OSV の説明と参考情報、同じ脆弱性を持つ他の資産、その資産の収集履歴が表示されます。イメージのスキャンでは、「Camada」（レイヤー）に、パッケージがどのレイヤーから来たかと、修正がベースイメージと Dockerfile のどちらで必要かが表示されます。Jira を設定している場合は、「Abrir ticket no Jira」（Jira でチケットを作成）で検出結果のチケットを作成できます。そこからトリアージを行い、クエリの前後の検出結果に移動できます。Esc キーまたは「Fechar」（閉じる）で表に戻ります。

  6. トリアージする

    最初の列で検出結果にチェックを入れます。表示されるバーで Revisado（確認済み）、Falso positivo（誤検知）、Risco aceito（受容済みリスク）、Reabrir（再オープン）のいずれかを選び、期限（ある場合）と理由を入力して、「Aplicar triagem」（トリアージを適用）をクリックします。Falso positivo と Risco aceito では理由の入力が必要です。すべての操作は Auditoria（監査）に記録されます。

クエリの例
severidade >= alta e corrigivel
pacote ~ openssl e (fonte = maquina ou fonte = container)
cve em (CVE-2022-37434, CVE-2024-3094)
ip em 172.30.0.0/24 e visto_em > -7d
"nginx" ordenar por epss desc
estado = novo e severidade >= alta
triagem = risco_aceito ordenar por prazo asc
tag = ambiente:producao
camada = base e corrigivel
クエリの演算子
演算子意味
= と !=等しい、または等しくない。versao = 1.2.* のように、* をワイルドカードとして使えます。
> >= < <=より大きい、またはより小さい。重大度、EPSS、ポート、日付に使えます。
~ と !~テキストを含む、または含まない。
em (a, b)リストに含まれる。IP の場合は、ip em 10.0.0.0/24 のように範囲も指定できます。
existeフィールドに値がある。
e, ou, não, ( )条件を組み合わせたり、まとめたりします。and、or、not、in も使えます。
検出結果の取得元

表には、各対象で最後に完了したスキャンが使われます。サーバー群では各マシンが個別に扱われ、最新のスキャンでアクセスできなかったマシンについては、そのマシンで最後に成功した収集が使われます。CVE の検索結果は含まれません。同じパッケージが、サーバー群のスキャンですでに表示されるためです。

修正済み、誤検知、受容済みリスクの検出結果は、クエリでそれらを指定しない限り表に表示されません。概要には非表示の件数が示され、それらを表示するためのショートカットもあります。

履歴に基づく検出結果の状態
状態表示される条件
Novo（新規）この対象で、これまで一度も出現したことのない検出結果です。
Ativo（アクティブ）前回の収集から引き続き存在しています。
Reapareceu（再発）完全な収集で一度消えた後、再び出現しました。
Corrigido（修正済み）完全な収集で出現しなくなりました。部分的な収集では修正を証明できないため、その場合の検出結果は、部分的な収集である旨の警告付きで Ativo のままになります。「regras do sudo não verificadas」（sudo のルールは未確認）のような警告は、それに依存する部分だけを部分的な収集として扱います。
検出結果パネルのデータはどこから来ますか？

CVSS、EPSS、悪用の状況、パッケージ、修正はスキャンから取得します。説明、日付、弱点（CWE）、参考情報は OSV から取得します。DockScan のサーバーがパネルを開いたときに取得し、1 日保存します。インターネットに接続できない場合も、パネルは残りの情報を表示し、OSV が応答しなかったことを知らせます。

履歴には資産の最近の収集が表示されます。Encontrado（検出）、Não encontrado（未検出）、または不在が修正の証明にならない場合の Coleta parcial（部分的な収集）です。ページのアドレスには ?achado= が付くため、リンクから同じ検出結果を直接開けます。

DockScan は優先度をどのように決めますか？

各脆弱性には 4 つの優先度のいずれかが付き、画面にはそれぞれの理由が表示されます。

  1. Corrigir agora（今すぐ修正）：悪用が確認済みのもの（KEV）。悪用される可能性（EPSS）が 10% 以上で、パッケージが使用中か、ネットワークから到達できるもの。または、重大度が緊急で、ネットワークから到達できるもの。
  2. Esta semana（今週中）：EPSS が 10% 以上のもの。または、重大度が緊急か高で、EPSS が 1% 以上か、使用中か、ネットワークから到達できるもの。
  3. Planejar（計画）：上記以外で重大度が緊急または高のもの、EPSS が 1% 以上のもの、重大度が中ですでに修正があるもの。
  4. Acompanhar（経過観察）：それ以外のすべて。

インストールされていても、どのプロセスにも読み込まれていないパッケージは、優先度が 1 段階下がります。CVE のない設定の検出結果は、重大度に従います。検索するには、prioridade = agora、em_uso、または exposto を使います。

どのフィールドを検索できますか？

使用できるフィールドは、severidade、cve、regra、titulo、pacote、versao、ecossistema、correcao、corrigivel、fonte、ativo、ip、porta、container、local、epss、kev、prioridade、em_uso、exposto、camada、novo、visto_em、estado、triagem、primeiro_visto、corrigido_em、prazo、tag、scan です。各フィールドの説明は、画面上のヘルプ「Como consultar」（検索方法）にあります。

はい／いいえで答えるフィールドを単独で書くと、「sim」（はい）とみなされます。kev は kev = sim と同じ意味です。日付には 2026-11-01、-7d、+30d、-24h、hoje（今日）、ontem（昨日）を指定できます。EPSS には 0.1 または 10% を指定できます。

トリアージの期限はどのように機能しますか？

Revisado、Falso positivo、Risco aceito には、最長 2 年の期限を設定できます。期限が切れると、検出結果は未対応（aberto）に戻り、期限切れとしてマークされて再び表に表示されます。期限が近い例外を確認するには、triagem != aberto e prazo < +30d で検索します。

タグと保存済みビューはどう作成しますか？

タグは ambiente:producao や time:plataforma のような categoria:valor（カテゴリ:値）の形式で、クエリによって定義します。対象の検出結果を選ぶクエリを書き、「Criar tag com esta consulta」（このクエリでタグを作成）をクリックして、カテゴリと値を入力します。クエリに一致するすべての検出結果に、今後のスキャンの分も含めてタグが付きます。その後は tag = ambiente:producao や tag = ambiente:* で絞り込んだり、タグでグループ化したりできます。タグは「Tags」（タグ）パネルに、それぞれが付いている検出結果の件数とともに表示されます。

保存済みビューは、クエリとグループ化の設定に名前を付けて保存したものです。「Salvar como visão」（ビューとして保存）で保存し、あとで「Visões salvas」（保存済みビュー）から選びます。タグとビューは、このインスタンスのすべてのユーザーに共通です。

修正計画とは何ですか？

「Agrupar por」で「Plano de correção」（修正計画）を選びます。各行はインストール済みのパッケージ 1 つに対応し、脆弱性の数、最も高い重大度、影響を受ける資産、更新先のバージョンが表示されます。一覧のパッケージを更新すると、その行の脆弱性がまとめて解消されます。

ターミナルから検索できますか？

はい。画面と同じクエリ言語を使い、インターフェースのデータを読み取って検索できます。

dockscan achados severidade >= alta e kev --data-dir ~/.dockscan
dockscan achados estado = novo --formato csv > novos.csv

--formato を指定しない場合は、表形式で出力されます。json または csv を指定すると、画面からのエクスポートと同じデータが出力されます。

クエリでエラーが表示された

メッセージには不足している内容とその位置が示され、カーソルが問題の箇所に移動します。よくあるエラーは、フィールド名の誤り、そのフィールドには使えない演算子（kev に対する > など）、閉じていない引用符や括弧です。

修正状況を追跡する

対象を修正した後に分析を再実行し、結果を比較して何が変わったかを確認します。

  1. 同じ対象で新しいスキャンを実行する

    同じ種類の分析と同じ対象名を使います。IP の選択とカバレッジのオプションも同じにしておきます。

  2. 「Comparar scans」（スキャンの比較）を開く

    完了した結果のページで Comparar scans をクリックします。メニューから Baselines（ベースライン）を開くこともできます。現在のスキャンと、比較可能な基準のスキャンを選びます。

  3. 3 つのグループを確認する

    Novos（新規）は、現在のスキャンで新たに出現した項目です。Persistentes（継続）は、引き続き存在している項目です。Corrigidos（修正済み）は、基準のスキャンにはあり、現在の結果には出現しない項目です。項目を開いて、変化の内容を確認します。

比較する前に

照会の無効化、収集エラー、Allowlist（許可リスト）の変更によって、結果が変わることがあります。「Corrigido」（修正済み）は、この比較においてその検出結果が報告されなくなったことを意味します。両方のスキャンの証拠と警告を確認してください。

Allowlist で例外を扱うには？

Allowlist を開き、1 行に 1 つずつルール、パッケージの場所、または識別子を入力して、Salvar allowlist（許可リストを保存）をクリックします。# で始まる行はコメントです。

エントリは次回以降のスキャンに適用され、該当する検出結果は不合格の判定から除外されます。過去の履歴はそのまま残ります。各エントリの適用範囲を確認してください。1 つのパッケージに複数の脆弱性が含まれることがあります。

サーバー群を分析する

ホストを登録すると、保存したインベントリを使って、実行中のコンテナとその設定を分析できます。

  1. 「Frota」（サーバー群）を開いてインベントリを入力する

    1 行に 1 つずつ、SSH アクセスのオプションとともに IP を入力します。DockScan サーバーは、SSH でホストに到達でき、鍵または資格情報の保管庫によるアクセス手段と、読み取りに必要な権限を持っている必要があります。資格情報の保管庫は Frota ページ内にあります。

  2. 保存して分析を開始する

    Salvar inventário（インベントリを保存）をクリックし、続いて Configurar varredura（スキャンを設定）をクリックします。「Novo scan」（新規スキャン）で IP を選び、ポリシーを調整して、「Iniciar varredura por IP」（IP によるスキャンを開始）をクリックします。

  3. 各ホストを確認する

    結果画面でホストを開き、マシンとコンテナの検出結果を確認します。アクセスの失敗や収集に関する警告もあわせて確認します。最後のスキャンを確認するには、「Frota」に戻ります。

  4. Inventário でマシンを確認する

    スキャンの後、「Inventário」（インベントリ）に見つかったマシン、コンテナ、サービスが、IP 範囲ごとにまとめたマップまたはリストで表示されます。マシンをクリックするとコンテナとサービスが開きます。IP を探すには検索とフィルターを使います。

SSH の資格情報の保管庫を設定する方法
  1. Frota で「Cofre de acesso SSH」（SSH アクセスの保管庫）に移動します。
  2. 名前、ユーザー、パスワード、許可するスコープを入力します。sudo は、そのアカウントで sudo を使うよう設定されている場合にのみチェックします。
  3. 「Salvar credencial」（資格情報を保存）をクリックします。パスワードは入力欄から消去され、インターフェースに再表示されることはありません。
  4. インベントリでは、cred=nome-da-credencial と書いてその資格情報を選びます。この場合もスコープは守られます。

SSH のホスト識別情報は、最初の接続時に登録されます。識別情報が変わった場合は、既知の識別情報の一覧からそのエントリを消去する前に、変更内容を確認してください。

各マシンで読み取る内容

収集には、マシンにもともとあるもの、つまりシステムコマンドと、/proc および /etc のファイルだけを使います。Python やエージェントをインストールする必要はありません。ss や ps がない最小構成のマシンでは、ポートとプロセスの情報をカーネルから直接取得します。

  1. システムパッケージ：Debian と Ubuntu（dpkg）、Alpine と Wolfi（apk）、Rocky Linux、AlmaLinux、Red Hat Enterprise Linux、SUSE Linux Enterprise、openSUSE Leap、Azure Linux、openEuler、Amazon Linux、Oracle Linux（rpm）。CentOS と Fedora は、DockScan が読み取れるアドバイザリのデータベースがないため、未検証として表示されます。
  2. Debian、Ubuntu、Rocky、SUSE のアドバイザリはソースパッケージを示します。そのため、libssl3 に該当する OpenSSL の脆弱性は openssl として表示されます。
  3. システムパッケージによってインストールされた言語のパッケージ（python3-setuptools の setuptools、Debian の Ruby の gem、Alpine の npm など）は、そのシステムパッケージで判定します。システムパッケージには、ディストリビューションの修正が含まれるためです。
  4. カーネルは、インストールされているパッケージではなく、実行中のバージョンで判定します。検出結果には CVE の総数が示され、今対応が必要なものが一覧で表示されます。悪用が確認済みのもの、悪用される可能性が 1% 以上のもの、公開から数日しかたっていないもの、そして、すでにインストールされているカーネルで次回の起動時に修正される、重大度が緊急または高のものです。Amazon Linux と Oracle Linux では、カーネルのアドバイザリが OSV に含まれていないため、カーネルは未検証として表示されます。
  5. 言語のパッケージ（pip、npm、gems、Composer、NuGet）と Java ライブラリ（.jar、.war、.ear）。コンテナとマシンの両方が対象で、/home と /root も含みます。Go のバイナリは両方で（マシンでは Go 1.18 以降でコンパイルされたものだけ）、Rust のバイナリはコンテナで読み取ります。シェルのないコンテナでは、言語のパッケージは、docker cp でコピーしたアプリケーションのフォルダーから取得します。
  6. パッケージマネージャーを使わずにインストールされたプログラム。たとえば公式イメージの node、python、redis です。バージョンはファイルそのものから読み取り、何も実行しません。一覧はDockScan が認識するものにあります。
  7. Docker と Podman のコンテナ。root なしの Podman では、SSH で接続したユーザーのコンテナが対象になります。
  8. マシンと各コンテナのシステムのサポート終了。
  9. 脆弱なパッケージごとに、現在そのファイルを使用しているプロセスがあるかどうか。停止している Go バイナリは露出が低いと判断されます。Java ライブラリについては、DockScan は使用中であることだけを示します。サーバーが展開した .war は、ファイルを開いたままにせずに使われるためです。
CVE を調査する方法
  1. ツールのメニューから「Buscar CVE」（CVE を検索）を開きます。
  2. IP と、CVE または GHSA の識別子を入力します。
  3. 「Verificar CVE nos IPs」（IP で CVE を確認）をクリックします。選択したマシンから SSH でデータが収集されます。
  4. 検出箇所、収集日時、警告、使用状況の証拠を確認します。収集が不完全な場合、その対象が該当しないとは言い切れません。

パッケージは、IP による収集の際に自動的に特定されます。

インベントリの例
# Docker da máquina em que o DockScan está rodando
127.0.0.1 local=true

# Exemplo de host remoto: substitua pelo seu ambiente
deploy@host.exemplo.com:2222 key=~/.ssh/id_deploy

鍵のパスとローカルの Docker は、DockScan サーバーが動作するマシン上で解決されます。アクセスが許可されているホストだけを使ってください。

ネットワークを調べる

Rede（ネットワーク）モジュールは、許可された対象のポートとサービスを特定し、露出の証拠を収集します。

  1. 許可されたスコープを確認する

    Configurações（設定）→ Configurações de rede（ネットワーク設定）で、「Escopos de rede autorizados (IP/CIDR)」（許可されたネットワークスコープ）を確認します。分析が許可されているネットワークだけを含めてください。既定ではループバックが許可されています。

  2. 「Rede → Varrer a rede」（ネットワークのスキャン）を開く

    スキャンに名前を付けます。「IP, range, CIDR ou múltiplos alvos」（IP、範囲、CIDR、または複数の対象）の欄に、IP とネットワークを入力します。サーバーのマシンで試す場合は、127.0.0.1 を使います。「Importar alvos」（対象をインポート）から .txt のリストを読み込むこともできます。

    必要に応じて、除外対象を入力します。フォームに表示される対象数の見積もりと、許可されたスコープを確認します。

  3. プロファイルを選んでポートを確認する

    「Configuração da varredura」（スキャンの設定）で「Perfil」（プロファイル）を選び、「Portas」（ポート）を確認します。タイムアウト、速度、および「Detectar serviços」（サービスを検出）、「Detectar Docker」（Docker を検出）、「Auditar registries」（レジストリを監査）、「Analisar TLS」（TLS を分析）の各モジュールを確認します。

  4. 許可を確認して「Iniciar varredura」（スキャンを開始）をクリックする

    スキャンのページで進行状況を確認します。スキャンの一時停止、再開、終了には、「Pausar」（一時停止）、「Retomar」（再開）、「Parar」（停止）を使います。停止した場合も、それまでの部分的な結果は引き続き参照できます。

あとで確認できる場所

「Em andamento」（実行中）には、実行中のジョブが表示されます。「Histórico」（履歴）には、過去の分析が保存されています。見つかったホストとサービスを調べるには、「Hosts」（ホスト）と「Serviços」（サービス）を使います。

カバレッジの読み方

スキャンのページで、「Visualização」（表示）をホスト、ポート、TCP カバレッジ、サービス、検出結果の間で切り替えます。収集の範囲を把握するには、「Configuração e limitações」（設定と制限事項）を参照します。

カバレッジについて

タイムアウトは結論の出ない結果です

応答のないポートが閉じているとは限りません。応答のないホストも、停止しているとは限りません。比較したり調査を終えたりする前に、カバレッジの状態を確認してください。

スキャンではどのサービスを認識しますか？

スキャンでは、SSH、HTTP、TLS、Docker、レジストリ、Redis、PostgreSQL、MongoDB、MySQL に加えて、次のサービスをその応答から特定します。ログインはせず、何かを変更するコマンドも一切使いません。

  1. FTP：バナーからのバージョンと、FTPS が提供されているかどうか。提供されていない場合、ユーザー名、パスワード、ファイルは暗号化されずに送られます。
  2. SMTP：バージョン、STARTTLS、暗号化の前に提供されるログイン。
  3. RDP：サービスの露出と、セッションの前に NLA が必須かどうか。
  4. RabbitMQ：AMQP プロトコルから読み取るバージョン、TLS なしの接続、ポート 15672 の管理画面。
  5. Prometheus：ログインなしで開いている API と、node_exporter などのエクスポーターのメトリクス。

「Network Services Scan」（ネットワークサービスのスキャン）プロファイルには、これらのサービスのポートがあらかじめ含まれています。

2 つのネットワークスキャンを比較するには？

Rede メニューの「Comparar varreduras」（スキャンの比較）を開くか、結果画面の「Comparar」（比較）を使います。2 つの分析を選び、新規、削除、変更、変更なしの各項目を確認します。

比較可能なカバレッジがない項目は、「NotComparable」と表示されます。サービスが削除された、あるいはリスクが解消されたと判断する前に、対象、ポート、モジュールを確認してください。

クラウドに接続する

クラウドモジュールは AWS アカウントを読み取り、コンテナを露出させている要素（マシン、ファイアウォールルール、レジストリ、クラスター）を見つけます。Azure、Google Cloud、Kubernetes はすでに登録できますが、それらの読み取りは今後の段階で対応します。

  1. 読み取り専用の資格情報を作成する

    プロバイダーを選ぶと、必要最小限の権限と、資格情報を作成する手順が画面に表示されます。管理者ユーザーのキーは決して使わないでください。

  2. 「Nuvem」（クラウド）を開いてプロバイダーを選ぶ

    アカウントに名前を付け、各フィールドを入力します。リージョン、サブスクリプション、プロジェクト、名前空間によって、読み取れる範囲が決まります。

  3. 保存して「Testar conexão」（接続をテスト）をクリックする

    AWS では、テストによってクラウド上で実際にアクセスを確認し、使用された ID を表示します。ほかのプロバイダーでは、アカウントが検証されて保存されたことを確認します。

  4. 「Descobrir agora」（今すぐ検出）をクリックする

    検出は、ほかのスキャンと同じように扱われます。スキャンのページで開き、Resultados（結果）に記録され、ポリシーに基づいて Falhou（不合格）または Passou（合格）と判定されます。検出結果は fonte = cloud として Achados（検出結果）画面に、マシンは Inventário（インベントリ）に登録されます。読み取れないリージョンがあった場合、スキャンは不完全となり、どのリージョンかが表示されます。

  5. 必要に応じて編集または削除する

    「Editar」（編集）では、シークレットを空欄のままにすると、現在の値が維持されます。「Excluir」（削除）を使うと、アカウントとそのシークレットがサーバーから削除されます。

セキュリティ

シークレットは暗号化されますが、保存先はサーバーです

資格情報は保管庫のキーで暗号化され、画面に再表示されることはありません。ただし、DockScan サーバーの管理者権限を持つ人は、それらを読み取れます。登録するのは読み取り専用の資格情報だけにし、できれば有効期限付きのものにしてください。

kubeconfig が拒否されたのはなぜですか？

セキュリティ上の理由から、kubeconfig にはトークンまたは証明書が埋め込まれ、クラスターの CA が certificate-authority-data に含まれている必要があります。次のものは拒否されます。DockScan サーバー上でプログラムを実行することになる exec または auth-provider による認証、サーバー上のファイルを読み込むことになるファイルパス、insecure-skip-tls-verify、そして https:// で始まらないアドレスです。

DockScan はクラウドで何を探しますか？

インターネットに公開された管理用ポート（Docker API、kubelet、etcd、Kubernetes API、レジストリ、SSH）、すべてのポートを許可するルール、匿名で読み取れるレジストリや管理者ユーザーが有効なレジストリ、上書き可能なタグ、公開されたクラスター API、RBAC のないクラスター、トークンなしでメタデータサービスを受け付けるマシン、特権付きのワークロードです。

AWS では、登録したリージョンの EC2（マシンとセキュリティグループ）、ECR、EKS からこれらの情報を取得します。ロールの ARN を指定した場合、キーはそのロールを 15 分間のセッションで引き受けるためだけに使われ、読み取りはすべてそのロールで行われます。リソースを作成または変更する呼び出しは一切行いません。

「Descobrir agora」が表示されない

このボタンは、プロバイダーのコネクタが用意されていて、その SDK が DockScan サーバーにインストールされている場合に表示されます。AWS の場合は、pip install "dockscan[cloud]" でインストールします。SDK が不足している場合は、接続テストでも通知されます。

分析をスケジュールする

決めた間隔で分析を繰り返し、各回の結果を履歴で確認します。

  1. 「Agendamentos」（スケジュール）を開いて定期実行に名前を付ける

    間隔（分）と初回の実行日時を設定します。1 日 1 回実行するには、1440 分を指定します。インターフェースでは 5〜10080 分を指定できます。

  2. 対象とポリシーを入力する

    マシンの IP と不合格の基準を入力します。選択内容は定期実行に保存され、SSH アクセスには Frota（サーバー群）の設定が使われます。

  3. 「Criar agendamento」（スケジュールを作成）をクリックする

    作成した定期実行は「Scans agendados」（スケジュール済みのスキャン）に表示されます。手動で 1 回実行するには Executar agora（今すぐ実行）、以降の実行を止めるには Pausar（一時停止）、再び有効にするには Retomar（再開）を使います。スケジュールを削除しても、過去のスキャンは残ります。

定期実行のしくみ

スケジュールは、選択した IP で収集を繰り返し、マシンの現在のデータを特定します。インベントリにほかの IP を追加しても、作成済みの定期実行の対象は広がりません。

インターフェースを閉じても分析は続きますか？

ブラウザーのタブを閉じても、サーバーは停止しません。DockScan サーバーが動作している間、定期実行は続きます。Web サーバーを停止した状態で実行するには、インスタンスと同じデータディレクトリを指定して、次の独立したサービスを動かし続けてください。

python -m dockscan agendador --data-dir ~/.dockscan

サーバーもこのサービスも動いていない場合、定期実行は行われません。再び動き出すと保留中の 1 回分が実行され、実行されなかった回をすべて繰り返すことはありません。

アカウントとアクセス

各ユーザーは自分のユーザー名とパスワードでログインし、アカウントのロールによって、できる操作が決まります。これらはすべて Configurações（設定）で管理します。

  1. ユーザー名とパスワードでログインする

    ログイン画面では、アカウントのユーザー名またはメールアドレスを使います。「Manter conectado」（ログイン状態を保持）を選ぶと、このブラウザーでセッションが最長 7 日間維持されます。選ばない場合、セッションは 30 分間操作がないとき、または 12 時間で終了します。

  2. 初回ログイン時にパスワードを設定する

    アカウントを作成した人には、あなたに渡すための一時パスワードが発行されます。そのパスワードでログインすると、DockScan はどの画面を開くよりも先に、あなた自身のパスワードの設定を求めます。パスワードは 12 文字以上で、ユーザー名とは異なるものにしてください。

  3. Configurações でプロファイルを確認する

    メニューの最下部にある自分の名前をクリックします。プロファイルには、ユーザー名、メールアドレス、ロール、パスワードを変更した日時が表示されます。ここでは、名前とメールアドレスの変更、パスワードの変更ができるほか、ほかのブラウザーで開いているセッションを確認し、それぞれを終了することもできます。

  4. 管理者向け：チームのアカウントを作成する

    Usuários（ユーザー）で名前、ユーザー名、ロールを入力し、「Criar usuário」（ユーザーを作成）をクリックします。一時パスワードは Copiar（コピー）ボタンとともに一度だけ表示されるので、安全な経路で伝えてください。各アカウントでは、Editar（編集）で名前、メールアドレス、ロール、アカウントを有効にするかどうかを変更でき、Redefinir senha（パスワードをリセット）で新しい一時パスワードを発行でき、Excluir（削除）でアクセス権を取り消せます。

  5. 2 段階認証を有効にする

    Configurações で「Ativar a verificação em duas etapas」（2 段階認証を有効にする）をクリックし、認証アプリ（Google Authenticator、Microsoft Authenticator、Authy、2FAS）で QR コードを読み取り、表示された 6 桁のコードをパスワードと一緒に入力します。続いて表示される 10 個の復旧コードを保管してください。携帯電話をなくした場合、それぞれ 1 回ずつログインに使えます。以後、ログインではパスワードの後にコードを求められます。

ロールで許可されていない操作は、画面に表示されません。ロールの変更はすぐに反映され、ログインし直す必要はありません。DockScan では、有効な管理者が 1 人もいない状態にはできません。また、自分自身のロールを変更したり、自分のアカウントを無効にしたりすることはできません。

アクセスキー

アクセスキーを使うと、ユーザー名とパスワードなしで管理者としてログインできます。自動化やアクセスの復旧に使い、人が使う場合はアカウントを使ってください。キーの発行と取り消しは Configurações で行います。キーは一度だけ表示されます。

2 段階認証の必須化

Usuários（ユーザー）で、管理者は 2 段階認証を必須にする対象を選びます。なし、管理者、またはすべてのアカウントです。まだ有効にしていない人には、ほかの画面より先に有効化の画面が表示されます。自分のロールに必須化するには、先に自分のアカウントで有効にしてください。アクセスキーはコードを求めないため、管理者パスワードと同じように保管してください。

パスワードを忘れた

管理者に、あなたのアカウントで Redefinir senha を実行してもらってください。一時パスワードが発行されるので、次回のログイン時に自分のパスワードを設定します。開いているセッションはすべて終了します。

対応できる管理者がいない場合は、サーバーにアクセスできる人が、インスタンスと同じデータディレクトリを使って、ターミナルからパスワードを変更します。

dockscan usuarios senha --usuario SEU_USUARIO
2 段階認証の携帯電話をなくした

ログイン画面でパスワードの後に「Usar um código de recuperação」（復旧コードを使う）をクリックし、保管しておいたコードのいずれかを入力します。ログイン後、新しいコードを生成するか、いったん無効にして新しい携帯電話で有効にし直してください。

コードが残っていない場合は、管理者にあなたのアカウントで「Remover verificação」（認証を削除）を使ってもらいます。あなたのセッションは終了し、次回のログインではパスワードだけが求められます。管理者がいない場合は、サーバーのターミナルで次を実行します。

dockscan usuarios remover-verificacao --usuario SEU_USUARIO
コードが一致しない

コードは 30 秒ごとに変わり、それぞれ 1 回だけ使えます。アプリに今表示されているコードを入力し、携帯電話の日付と時刻が自動設定になっているか確認してください。間違ったコードを 5 回続けるとパスワードの入力に戻ります。誤りが多すぎると、15 分間は新しい試行がブロックされます。

セッションが終了したのはなぜですか？

セッションは、30 分間操作がなかったとき、12 時間が経過したとき（「Manter conectado」の場合は 7 日間）、ログアウトしたとき、自分の別のセッションから Configurações で終了されたとき、パスワードを変更したとき（ほかのセッションは終了します）、管理者がパスワードをリセットしたりアカウントを無効にしたりしたときに終了します。サーバーを再起動しても、セッションは終了しません。2 段階認証を有効にしたときも、ほかのセッションは終了します。また、管理者があなたの 2 段階認証を削除すると、あなたのセッションは終了します。

「O papel não permite esta ação」（このロールではこの操作は許可されていません）と表示された

あなたのアカウントには、その操作を行う権限がありません。たとえば、Analista ロールで Frota のインベントリを編集しようとした場合です。管理者に変更を依頼するか、ロールの調整を依頼してください。

開発中の機能

DockScan は開発中のツールです。バージョンによって画面や名称が変わることがあります。この章では、最近追加された機能と今後の予定を紹介します。

  17. マニュアルはポルトガル語、英語、スペイン語、フランス語、ドイツ語、日本語で読めます。言語はページ上部で選べます。

  19. Achados（検出結果）：履歴に基づく検出結果ごとの状態（novo、ativo、reapareceu、corrigido。それぞれ新規、アクティブ、再発、修正済み）、期限付きのトリアージと一括トリアージ、categoria:valor 形式のタグ、保存済みビュー、修正計画、列による並べ替え、ターミナルからの検索。
  20. Nuvem（クラウド）：AWS（EC2、セキュリティグループ、ECR、EKS）をスキャンとして読み取り、検出結果は Achados に、マシンは Inventário（インベントリ）に登録。
  21. Frota（サーバー群）：インベントリでは IP ごとに 1 つのアクセス設定とし、保存時に検証。インベントリから外したマシンは Achados からも外れ、その履歴は Resultados（結果）に残ります。

よくある質問

結果を解釈する前に、分析の状態を確認してください。

スキャンで検出結果が 1 件も返されませんでした。すべて安全ですか？

分析が完了しているか、フィルターで項目が隠れていないか、失敗や不完全な収集の警告が出ていないかを確認してください。CVE の照会が無効になっていないか、Allowlist（許可リスト）にエントリがないかも確認します。検出結果がないということは、その実行において、実施したカバレッジの範囲内で報告された項目がなかったという意味です。

IP が受け付けられない

DNS 名、ユーザー、ポート、範囲を含めずに、マシンの IPv4 または IPv6 アドレスを入力してください。SSH のポートが既定と異なる場合は、Frota（サーバー群）のインベントリで設定します。

マシンに接続できない

DockScan サーバーからその IP に到達できるか、SSH が利用できるか、保管庫の資格情報のスコープにそのアドレスが含まれているかを確認してください。スキャンのエラーと警告を読み、収集に失敗した部分を特定します。

サーバー群のホストが失敗した

インベントリのアドレス、ユーザー、ポート、鍵のパスを確認してください。SSH アクセスと Docker への問い合わせは、サーバーのマシンから動作する必要があります。ホストごとの警告を読んでください。アクセスに失敗すると、その対象の収集ができないことがあります。

ネットワークスキャンで対象が拒否された

入力したのが IP、範囲、CIDR のいずれかであり、それが「Escopos de rede autorizados」（許可されたネットワークスコープ）の範囲内にあるかを確認してください。ホスト名や URL は、この欄には入力できません。除外対象とホスト数の上限も確認します。全体の設定は、実行中のスキャンがないときに調整してください。

時刻はどのタイムゾーンで表示されますか？

ブラウザーのタイムゾーンで、「02/11/2026, 14:21 BRT」のように略称を添えて表示されます。サーバーは各時刻をタイムゾーン付きで記録するため、別の地域から開いた人にも、その人にとって正しい時刻が表示されます。

比較で新しい項目が表示されない

比較可能な過去の基準があるか、比較が有効になっているかを確認してください。同じ IP と同じカバレッジのオプションを使います。カバレッジの警告、Allowlist、「Somente novos」（新規のみ）フィルターを確認してください。初回の実行では、新しい項目を判別するためのベースラインがありません。
